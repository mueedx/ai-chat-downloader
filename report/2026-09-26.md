# Daily report - 26 September 2026

## What shipped

The AI Chat Downloader repository, initialised as a standalone project and built out to its first
release candidate. It is a Manifest V3 Chrome extension that exports the AI conversation open in
the current tab to Markdown, plain text, DOCX, or PDF, across six sites: ChatGPT, Claude, Gemini,
DeepSeek, Qwen, and Kimi. The work was driven end to end with GitHub Spec Kit, and the DOCX and
PDF writers were ported from the working zero-dependency exporters in the sibling `nicekit-app`
project, adapted for an extension context where `Buffer` does not exist.

The deliberate stance throughout is that a failed extraction must be visible. Zero readable turns
writes no file and reports the selectors that were tried, a partially readable conversation is
exported with the skipped-turn count stated in both the popup and the file, a reply that was still
streaming is marked incomplete, and no adapter is marked verified until a human has run it against
a live signed-in conversation.

## Later - runtime coverage and two real fixes

Added `test/runtime.test.js`, which exercises the files the other suites never loaded: the
content script's message handler, the preference store's validation, and the service worker's
download request. Writing it surfaced two defects that the earlier suites could not see. The popup
read the conversation title from a cache variable that had been removed, which threw on every
supported site, and the DOM engine compared lower-case tag names against an upper-case ignore list,
so a "Copy" button and a copy-button row leaked into exports and images never became notes. Both
are fixed and both now have a test. The DOM engine also gained a rule for list items, so a bulleted
answer still reads as a bulleted answer in plain text.

## Later - the export path itself is now tested

Added `test/popup.test.js`, which runs the real popup script against a stubbed element surface and
clicks through the flow: four formats offered, the site labelled unverified, a format switch that
changes the written file, a turn range that reaches the filename, warnings for unreadable,
incomplete, and partial captures, and two failure paths that must not reach the download call. The
last one matters most, because claiming a file was written when it was not is the failure this
whole project is built to avoid.

## Not done, and why

No adapter has been run against a live signed-in conversation. That needs accounts and a browser
session that are not available in this environment, so `docs/supported-sites.md` records every
site as unverified with no date, and the options page shows the same. Live verification is the
next task and it gates the store submission.
