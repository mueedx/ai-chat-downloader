# Daily report - 26 September 2026

## What shipped

The AI Chat Downloader repository, initialised as a standalone project and built out to its first
release candidate. It is a Manifest V3 Chrome extension that exports the AI conversation open in
the current tab to Markdown, plain text, DOCX, or PDF, across six sites: ChatGPT, Claude, Gemini,
DeepSeek, Qwen, and Kimi. The work was driven end to end with GitHub Spec Kit, and the DOCX and
PDF writers were ported from the working zero-dependency exporters in the sibling `nicekit-app`
project, adapted for an extension context where `Buffer` does not exist.

The deliberate stance throughout is that a failed extraction must be visible. Zero readable turns
writes no file and reports the selectors that were tried, a partially readable conversation is
exported with the skipped-turn count stated in both the popup and the file, a reply that was still
streaming is marked incomplete, and no adapter is marked verified until a human has run it against
a live signed-in conversation.

## Later - runtime coverage and two real fixes

Added `test/runtime.test.js`, which exercises the files the other suites never loaded: the
content script's message handler, the preference store's validation, and the service worker's
download request. Writing it surfaced two defects that the earlier suites could not see. The popup
read the conversation title from a cache variable that had been removed, which threw on every
supported site, and the DOM engine compared lower-case tag names against an upper-case ignore list,
so a "Copy" button and a copy-button row leaked into exports and images never became notes. Both
are fixed and both now have a test. The DOM engine also gained a rule for list items, so a bulleted
answer still reads as a bulleted answer in plain text.

## Later - the export path itself is now tested

Added `test/popup.test.js`, which runs the real popup script against a stubbed element surface and
clicks through the flow: four formats offered, the site labelled unverified, a format switch that
changes the written file, a turn range that reaches the filename, warnings for unreadable,
incomplete, and partial captures, and two failure paths that must not reach the download call. The
last one matters most, because claiming a file was written when it was not is the failure this
whole project is built to avoid.

## Later - a repeatable verification procedure

Added `docs/verification-checklist.md`, so checking a site is a fixed ten-step procedure rather than
whatever a given person remembers to try. It says to use a throwaway conversation, keep
indentation and blank lines inside a code block, test an image note, test an export while a reply is
still streaming, test a scrolled long conversation, and open all four files. It also states what to
record: the date in both the table and the adapter, the Chrome version, and which step failed if
one did. A site with a failing step stays unverified and the failing step becomes the adapter's
known issue.

Also added `test/options.test.js`, which covers the last untested surface: the per-site switches, the
default format, and the status board. The status board is now proven to read the adapter flags, so
marking a site verified really does change what the page says, and the test that asserts this
flips a flag rather than asserting on a literal.

## Later - full transcript capture, as its own spec

Opened `specs/002-full-transcript-capture` on its own branch and built the walk, because a partial
export of a long conversation is the worst wrong answer this extension can give and it currently
happens silently on every site that virtualises.

The walk has two phases, because the two problems are different: sitting at the top until the
container stops growing, which is how a site loads older turns, and then sweeping down a viewport at
a time. Positions are assigned directly, never animated, and the walk never clicks, types, or
submits. It is bounded by time and by steps, cancellable, and restores the reading position on every
path, using the proportion of the scroll when the container was replaced mid-walk.

A virtualised list recycles its elements, so the bottom of the conversation is gone by the time the
walk reaches the top. The walk therefore reads at every step and a new `src/core/merge.js` joins
the reads on the longest overlap, keeping the longer read when two do not overlap rather than
guessing an order.

The tests found two real defects while being written. The walk reported reaching the bottom after
running out of steps, which would have put a "complete" claim in the file for a capture that was
missing whatever was never scrolled to. And the final read could beat an earlier longer read, which
would have dropped the top of a conversation on any list that recycles. Both are fixed, and both now
have a test.

Every exported file now carries a completeness claim with a reason when it is incomplete, and the
reason distinguishes a preview read, a walk that is switched off, and a walk that stopped early,
because those read very differently to the person holding the file. The walk is disclosed in the
popup before the export, defaults on, and can be switched off globally and per site.

## Later - a real browser found what 138 tests could not

A screenshot of the loaded extension in Chrome showed `Uncaught ReferenceError: window is not
defined` at `src/background.js:49`. The service worker is loaded on its own, in a scope with no
`window`, and the file ended with `})(window.AIChatDownloader);`. It threw during evaluation, so
the worker never registered its download listener and every export silently failed to write a file.

Every test had passed, because the shared harness sets `globalThis.window = globalThis`, which
makes a worker-only bug invisible. That is the more serious finding: not the missing `window`, but a
test setup that lied about the environment.

Three fixes. `background.js` now resolves the global scope itself and creates the namespace, with
the reason written down so the next person does not "simplify" it back. `test/worker.test.js`
evaluates the file in a real `vm` context that has no `window` or `document`, and asserts it
registers a listener and starts a download. `npm run check:manifest` now fails the build if the
service worker mentions `window`, `document`, `location`, or `navigator`, or depends on the
namespace bootstrap the manifest does not load there, and if the content script list does not load
the namespace first. The checker was verified by breaking the file on purpose and watching it fail.

The general rule went into `RULES.md` and `AGENTS.md`: when a test needs a global the target scope
does not have, simulate the target scope rather than papering over it.

## Later - the window was never put back

While working out why the reported service worker error might persist, I checked whether the walk
restores the window scroll as well as the transcript's own container. It did not. The walker read
and wrote `doc.scrollY`, and a Document has no such property, so the read was always undefined and
the write created a meaningless property on the document object. On a site that scrolls the window
rather than an inner element, an export would have left the reader at the bottom of the
conversation, with no warning, while the export itself succeeded.

Worse, the obvious fix would have thrown. `window.scrollY` is a getter-only property, and the
walker is inside a strict function, so assigning to it raises a TypeError rather than scrolling.
The walk would have failed after capturing the transcript.

The walker now takes a `viewport`, calls `scrollTo(0, y)` when the viewport offers it, and falls
back to assignment only for viewports that allow one. `src/content.js` passes `window`. Two new
cases cover it, including a viewport whose `scrollY` getter throws on assignment, which is what a
real window does. A standalone check in a vm with a window shaped like Chrome's confirms
`scrollTo(0, 250)` is called with the saved position and that no assignment is attempted.
