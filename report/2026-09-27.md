# Daily report - 27 September 2026

## What shipped

The diagnostic half of feature 003, and the fix for the popup crash that came with it.

The crash: the popup failed with `Cannot read properties of undefined (reading
'describeDiagnostic')` on `src/popup.js:153`. The `NS.dom` namespace does not exist in the popup
scope, because `src/popup.html` does not load `core/dom.js`. The failure branch was written as if
it did. The test suite passed anyway, because the shared harness loaded every source file into
one context and handed the popup a module its real scope has never had.

The fix has two parts. `src/content.js` now words the diagnosis, because the content script is the
scope that read the page, and sends it as `detail`. `src/popup.js` prints that string. The popup
page loads no DOM engine, which is the state the code should have been in from the start.

The guard: `loadPage(htmlName)` in `test/harness.js` loads exactly the scripts an extension page
lists in its HTML, and the popup and options suites now use it. A page that reaches for a module
its own HTML omits fails in the suite instead of in someone's browser. This is the rule the
service-worker bug in feature 002 already followed, applied to the other two scopes.

Also restored from the Cline checkpoint `e3a54f1`: `NS.dom.diagnose` and `NS.dom.describeDiagnostic`
in `src/core/dom.js`, the same-origin frame fallback in `extractChat`, `specs/003-deepseek-message-detection/spec.md`,
and `test/diagnosis.test.js`. Two of the recovered test cases had never been run and failed against
the recovered code, so `test/minidom.js` grew the universal selector and a `SyntaxError` on an
unparsable selector, which is what a browser does and what makes `unsupported` distinguishable from
a count of zero.

## Not done

The DeepSeek selector repair itself, which is the product fix for `Messages 0` (FR-006, FR-009).
No adapter was changed, so `docs/supported-sites.md` is untouched and DeepSeek remains
`verified: false`. It needs a real capture of a live conversation, not a guess.

`test/fixtures/deepseek-live.html` is untracked and was written by hand, not captured from a live
page. Its title reads `JS window error - DeepSeek` and it carries authoring comments, so it is not
evidence of anything and no test loads it. It should be replaced by a real capture before it is
committed.

The recovered frame test used DeepSeek selectors that the adapter does not have, and markup that
matches no tier. It now runs on the ChatGPT adapter, which tests the frame fallback in `dom.js`
without asserting DeepSeek markup nobody has verified.

## Changes

- Fixed the popup crash by moving the diagnosis wording into `src/content.js` and reading
  `result.detail` in `src/popup.js`.
- Added `loadPage` to the test harness and switched the popup and options suites to it, so a page
  can no longer pass a test using a module its HTML does not load.
- Restored the diagnostic engine, the frame fallback, the 003 spec, and the diagnosis suite from
  the Cline checkpoint.
- Taught minidom the universal selector and to throw on a selector it cannot parse.
- Pointed `.specify/feature.json` at `specs/003-deepseek-message-detection`.
